# ADR-007: Deliver the Calendar Entry as an iCalendar file only

**Status:** Accepted
**Date:** 2026-11-08
**Requirements:** NFR-048, NFR-042, C-021, FR-046, FR-047

## Context

A visitor takes an event into their calendar from its Event Page (FR-047). The function must work
without script (C-021), and a public page issues no request to another host (NFR-042). The Date
Text is free text and the Display Date only decides the listing, so the period comes from the
First Day and Last Day of the event (FR-046). Decided with the product owner on 2026-11-08.

## Decision

The Event Page links to an iCalendar file (RFC 5545, `text/calendar`) generated by the application
itself for the event (NFR-048): one all-day entry from the First Day to the Last Day, without time of
day or time zone. The link is offered only while both days are recorded.

## Consequences

- Works in every calendar app that imports iCalendar files, on phone and desktop, without script.
- The entry is a copy: a later change of the event does not reach the visitor's calendar on its own.
- **Alternatives considered:** a prepared link into Google Calendar or another online calendar —
  declined, because it hands the event to a third party and serves only the calendars it happens to
  list; deriving the period from the Date Text or the Display Date — declined, because it would be a
  guess.
